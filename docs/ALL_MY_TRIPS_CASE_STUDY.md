## 문제 해결 1 — 예약부터 검표까지 끊기지 않는 흐름

### 문제

예약, 결제, 발권과 현장 검표가 서로 분리되면 상태가 어긋나거나 중복 처리가 발생할 수 있습니다.

### 해결

예약 생성부터 결제 승인, QR 티켓 발급, 관리자 검표까지 상태 전이를 하나의 도메인 흐름으로 연결했습니다. 결제 QR에는 HMAC-SHA256 서명과 5분 만료를 적용하고 같은 티켓의 중복 검표를 거부하도록 구성했습니다.

## 문제 해결 2 — 한정 재고의 동시 예약

### 문제

재고 확인과 차감이 분리되어 실행되면 동시에 들어온 요청이 같은 재고를 가져갈 수 있습니다.

### 해결

Redis Sorted Set과 Lua 스크립트로 대기열 등록·순번·입장 상태를 관리했습니다. 실제 재고 차감은 PostgreSQL 행 잠금과 잔여 수량 조건부 UPDATE로 처리해 초과 판매를 방지했습니다. 단위·동시성 테스트와 k6 부하 테스트를 분리해 처리량과 데이터 정확성을 각각 검증했습니다.

### 결과

- 재고 10개에 사용자 30명 동시 접근
- 예약 성공 10건
- 재고 소진 거절 20건
- 요청 실패율 0.0%

## 문제 해결 3 — 반복 가능한 운영 배포

### 문제

수동 배포는 작업자마다 과정이 달라지고, 재배포와 롤백 과정에서 실수가 발생할 수 있습니다.

### 해결

GitHub Actions에서 빌드·테스트·CodeQL을 수행한 뒤 OIDC, S3, SSM과 systemd를 통해 EC2에 배포하는 흐름을 구성했습니다. Nginx와 Cloudflare로 HTTPS를 적용하고 배포일지와 롤백 절차를 문서화했습니다.
