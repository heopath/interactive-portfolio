# Development Roadmap

## 목표

게임을 즐기지 않아도 핵심 역량을 빠르게 파악할 수 있고, 탐색하면 성장 과정까지 기억에 남는 포트폴리오를 완성한다.

## Phase 1 — 콘텐츠 확정

- [ ] 이름, 희망 직무, 한 줄 소개 확정
- [ ] 대표 프로젝트 3개 선정
- [ ] 프로젝트별 담당 역할과 실제 구현 기능 구분
- [ ] 문제 → 선택 → 구현 → 결과 형식의 사례 작성
- [ ] 프로젝트 화면 이미지 또는 GIF 준비
- [ ] 연락 방법과 이력서 PDF 준비

완료 기준: 계획 중인 기능과 실제 구현한 기능이 명확히 구분되고, 모든 프로젝트 설명을 본인이 증명할 수 있다.

## Phase 2 — 게임 비주얼

- [ ] 64×64 캐릭터 디자인 확정
- [ ] Idle 4프레임 제작
- [ ] Walk 6~8프레임 제작
- [ ] 좌우 방향 전환 적용
- [ ] Java·DB·Spring·AI 구역별 배경 오브젝트 제작
- [ ] 스프라이트 로딩 실패 시 대체 UI 제공

선택 작업:

- Inspect, Wave, Clear 동작
- 배경 패럴랙스
- 효과음과 음소거 버튼

## Phase 3 — 프로젝트 상세 경험

- [ ] 프로젝트 대표 이미지
- [ ] 담당 역할
- [ ] 핵심 기능
- [ ] 가장 어려웠던 문제와 해결 과정
- [ ] 기술 선택 이유
- [ ] 결과와 개선점
- [ ] GitHub·시연 영상·배포 링크

## Phase 4 — 품질 검증

- [ ] 모바일 세로형 탐색 검증
- [ ] 키보드만으로 모든 콘텐츠 접근
- [ ] 모션 감소 설정 검증
- [ ] Lighthouse 성능·접근성 점검
- [ ] 이미지 WebP 변환과 지연 로딩
- [ ] Chrome·Edge·모바일 브라우저 점검

## Phase 5 — GitHub Pages 배포

- [ ] Vite `base`를 `/interactive-portfolio/`로 설정
- [ ] `.github/workflows/deploy.yml` 추가
- [ ] 개인정보와 비밀정보 최종 점검
- [ ] 저장소 공개 전환
- [ ] Pages Source를 GitHub Actions로 설정
- [ ] 배포 URL과 README 연결
- [ ] 필요 시 개인 도메인 연결

## Phase 6 — 선택적 백엔드 확장

다음 기능이 실제로 필요할 때만 Oracle Cloud를 사용한다.

- AI 포트폴리오 안내 챗봇
- Spring Boot API
- 방문자 통계
- 관리자용 콘텐츠 수정
- 데이터베이스가 필요한 기능
